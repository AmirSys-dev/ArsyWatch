Tapi yang paling penting hari ni bukan kod. Ia satu dokumen.

### 1. Kontrak API (docs/api.md)

PRD tulis `docs/api.md` sebagai **TBD**. Itu masalah besar sebenarnya. Kalau
kontrak tak ada, tiga benda — firmware, server, dashboard — semua orang akan
reka bentuk sendiri. Firmware hantar `rssi`, server expect `signal_strength`.
Dua minggu kemudian baru perasan. Jadi saya tulis kontrak dulu, beku dia,
baru mula kod.

Keputusan dalam kontrak yang saya fikir betul:

- **Masa datang dari server, bukan ESP.** ESP8266 tak ada RTC. Jam dia reset
  setiap kali reboot. Kalau kita percaya masa dari ESP, data akan lompat-lompat.
  Jadi ESP hantar `uptime_ms` sahaja, server yang cop masa.
- **ESP hantar MAC mentah, server yang hash.** Ini nampak pelik — kenapa tak
  hash dalam ESP terus? Sebab salt mesti tinggal di server. Kalau salt masuk
  dalam firmware, ia masuk dalam repo awam, dan sesiapa boleh brute-force hash
  tu. Lagipun heap ESP cuma 40KB, SHA-256 setiap MAC akan makan memori.
- **Channel 1-14 sahaja.** ESP8266 radio 2.4 GHz sahaja. Ni bukan pilihan, ni
  had fizikal.

### 2. Server

Node + Express + better-sqlite3. Pilih SQLite sebab VPS cuma 1GB RAM — tak
mampu nak jalankan Postgres sebagai proses berasingan untuk data sekecil ni.

Benda yang saya paling risau: **jangan simpan MAC mentah**. Ada ujian khusus
untuk ni. Ujian tu hantar MAC, kemudian check seluruh database — pastikan
string MAC tu tak muncul di mana-mana. Kalau seseorang nanti tersilap tambah
`console.log(mac)` atau simpan ke column, ujian tu akan gagal.

Satu lagi: token peranti dibanding guna `crypto.timingSafeEqual`. Tapi kalau
kita banding terus, panjang berbeza akan keluar awal sebelum perbandingan
bermula — dan itu bocorkan maklumat. Jadi kedua-dua belah di-hash dulu kepada
32 bait tetap, baru banding. Ada ujian untuk kes ni juga.

## Benda yang makan masa (dan patut diingat)

**1. ESM import vs environment variable**

26 ujian gagal serentak. Punca: saya letak `process.env.MAC_SALT = '...'` di
atas fail ujian. Tapi ES module import diangkat (hoisted) ke atas — jadi
`config.js` baca `process.env` **sebelum** baris saya berjalan. Config dah
snapshot nilai kosong.

Penyelesaian: fail `test/env.js` berasingan, diimport sebagai baris pertama.
Kena ingat ni untuk projek Node mana-mana.

**2. Ujian tak mahu berhenti**

Node guna `fetch` global (undici), dan undici simpan socket hidup. Jadi
`server.close()` tak pernah selesai. Ujian lulus semua tapi proses tergantung
selamanya. Guna `--test-force-exit`.

**3. SVG pecah sebab satu aksara**

Diagram aliran scan tu SVG dengan animasi CSS. Dalam komen CSS saya tulis
perkataan yang ada `<g>`. XML baca `<style>` sebagai markup, jadi ia ingat
`<g>` tu tag pembuka. Seluruh fail pecah.

Yang menarik: saya baru tahu bila saya buka fail tu dalam browser. Kalau saya
percaya sahaja, saya akan hantar diagram yang rosak.

Penyelesaian: `<![CDATA[ ... ]]>`.

## Satu benda yang saya silap faham

`design-preview.html` ada AP bernama `HomeNet_5G` pada channel 36.

Channel 36 tu 5 GHz. **ESP8266 tak boleh nampak 5 GHz langsung.** Jadi data
contoh tu mustahil — ia menggambarkan benda yang hardware ni tak akan pernah
hasilkan.

Dah betulkan. Sekarang preview tu tunjuk AP 2.4 GHz sahaja, plus satu AP
tersembunyi (SSID kosong) sebab tu keadaan sebenar yang firmware akan jumpa.

Pelajaran: data contoh yang cantik boleh sembunyikan had sebenar sistem.
